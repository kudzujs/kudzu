# Kudzu Project Rules

## Product Direction

- Kudzu's primary product goal is AI-assisted migration of ordinary React-shaped TSX to static deploy artifacts.
- Ordinary common React-shaped TSX should migrate with minimal source restructuring. Prefer compiler specialization over asking applications to replace declarative components, collections, hooks, or conditions with imperative DOM code; this direction is product-wide, not tied to Stay or any other application.
- Preserve familiar function components, props, children, JSX, hooks, and event-handler syntax where Kudzu can compile them safely.
- The output remains pre-rendered HTML, CSS, and only the route-specific ESM capabilities actually used. Static pages must ship no JavaScript.
- React, a VDOM, hydration, and a retained browser component tree remain forbidden.
- A small compiler-generated capability module is not a general client runtime. Route-specific effects and runtime path/query-parameter readers are allowed when the browser is the only place the value can exist.
- Native document navigation is the default. Do not add an SPA router unless a real migration fixture proves it necessary and the user explicitly approves it.
- Migration input may use a named or aliased `Link` import from `react-router-dom` with exactly one static root-relative `to` and native anchor props. The compiler prefixes `base`, lowers it to `<a href>`, and erases the package import. Dynamic or relative destinations, `NavLink`, router-only props, default/namespace imports, and non-JSX uses remain unsupported.
- A named or aliased `useParams` import from `react-router-dom` may be called directly without runtime arguments on a bracket page exporting `runtimeParams = true`. The compiler redirects it to Kudzu's existing pathname reader and erases the package import; build-known `getStaticPaths()` routes continue to use props.
- A named or aliased `useMatch` import from `react-router-dom` may directly initialize one top-level `const` from one exact static root-relative string pattern in route scope. Kudzu evaluates it case-insensitively from the build-known application route and erases the package import, adding no browser capability. Layout use, runtime-parameter pages, params, wildcards, query/hash patterns, trailing slashes, dynamic patterns, indirect calls, and pattern objects remain unsupported.
- A named or aliased `useSearchParams` import from `react-router-dom` may initialize one top-level `const [params]` or `const [params, setParams]` tuple. Direct top-level `const value = params.get("literal")` reads lower to nullable route signals initialized from `location.search`; the exact pagination form `const page = Number(params.get("literal")) || finiteNumber` and exact string fallback `const order = params.get("literal") || importedImmutableArray[staticIndex]` lower through the same signal and existing primitive binding evaluator. Direct setter calls from nested browser callbacks accept one synchronous inline updater over `URLSearchParams`; no options uses `history.pushState()`, while exactly `{ replace: true }` uses `history.replaceState()`. Dynamic names or indexes, direct-value setters, aliases, other methods on the outer params object, indirect reads, and broader wrappers remain unsupported.
- A named or aliased `useNavigate` import from `react-router-dom` may initialize one top-level `const navigate` binding. Direct calls from nested browser callbacks with one safe static root-relative destination lower to `location.assign()`; exactly `{ replace: true }` lowers to `location.replace()`. Dynamic or relative destinations, render-time calls, passed aliases, and other options remain unsupported.
- Before planning migration-related framework work, read `MIGRATION_ROADMAP.md`, `docs/next-architecture/0.9-semantic-compression.md`, `docs/next-architecture/0.9-implementation-plan.md`, `docs/next-architecture/0.9-baseline.md`, and `docs/next-architecture/0.9-benchmark-contracts.md`. Follow the first evidence-ready incomplete item and its session packet instead of inventing a new architecture.
- For every 0.9 semantic slice, begin with a real failing fixture, reduce it through native behavior, existing semantics, normalization, or an internal adapter in that order, and report semantic primitives, core passes/LOC, runtime concepts, browser bytes, fixtures, and benchmark deltas. A new semantic primitive requires architecture review after at least three unrelated real fixtures; fixture count does not itself authorize the primitive.

- New Kudzu source imports framework APIs from `@kudzujs/core`. Migration input may retain supported named hook imports from `react` plus default, namespace, or named `Fragment`; the compiler must erase those React module references and must never emit or execute React.
- Reduced Zustand migration syntax is contained by its compiler adapter and lowers to package-neutral `SharedStateIR` and `SharedActionIR` records before generic signal and handler consumers. Preserve existing Zustand source diagnostics and layout-lifetime behavior; do not expose a public store/adapter API or add a store runtime until an independent migration proves it necessary.
- Package imports may be referenced directly inside intrinsic event handlers or inline owned effect setup/cleanup callbacks, including inline callbacks passed directly within those effect callbacks. The compiler removes them from build-time component modules and preserves them only in bundled route handler/effect ESM; render-time, helper-indirect, and mixed references remain unsupported.
- One direct literal bare-package `import()` may remain inside an inline synchronous effect whose callee resolves lexically to a named React or Kudzu `useEffect` import and whose first statement is the exact dependency-state guard `if (!state) return`. Multi-entry builds share the deferred package chunk across route owners, route/navigation prefetch does not preload it, and the native document module map deduplicates requests. Relative, URL, render-time, event, indirect, async-effect, unguarded, multiple, and shadowed-hook dynamic imports remain unsupported; do not add a loader, retry cache, or prefetch registry.
- A named or default zero-argument custom hook imported from a relative TypeScript module may initialize one top-level `const` object destructuring. Its direct shorthand return may expose paired `useState` values/setters and callbacks that capture only those states/setters, including direct multi-state literal reset actions. One directly returned callback may own one private `null`-initialized timeout ref when it directly clears the previous timer, assigns a literal-delay `setTimeout()`, and one empty-dependency effect directly clears that timer on cleanup. Result aliases, defaults, rest, other private callback captures, dynamic delays, intervals, and dynamic return shapes remain unsupported.
- A named or default relative synchronous `useDebounce(value, delay)` hook may accept one direct primitive state and one numeric literal delay. It must directly initialize one state from `value`, own one dependency effect that assigns one `setTimeout(() => setter(value), delay)` and returns direct `clearTimeout()` cleanup, then return the debounced state. Kudzu specializes it through existing state/effect ownership; dynamic delays, non-primitive state, aliases, additional statements/effects, intervals, and missing cleanup remain unsupported.
- A function component may initialize one direct `const ref = createRef<T>()` from React migration input when the ref is attached exactly once to an intrinsic element. A relative outside-click hook may receive that ref and one inline direct literal setter callback when it owns one static document `mousedown` listener, tests `ref.current.contains(event.target)`, and removes the same listener in cleanup. Kudzu lowers `createRef()` to existing object-ref ownership and specializes the callback into effect scope; aliases, dynamic events, multiple refs/listeners, callback captures, and mismatched cleanup remain unsupported.
- A relative zero-argument custom hook may instead directly return `useContext(ContextIdentifier)` when the Context and its single Provider are declared together in one local or named relative TypeScript module. The Provider value must be a direct shorthand object of Provider-owned `useState` values, optional setters, and synchronous actions that capture only those pairs. An action-required setter may remain absent from the authored Provider value when its state value is exposed; the compiler adds that setter only to build scratch. Consumers may invoke selected actions directly or from nested intrinsic handlers; action-private state/setter fields receive compiler-owned collision-free local aliases when the consumer already declares the same names. Kudzu specializes the action into existing state operations and ships no function, Context runtime, or Provider tree. Fully hidden action state, exposed setters without state, dynamic Provider values, multiple Providers, action aliases, and private captures remain unsupported.
- Kudzu compiles only TypeScript modules reachable from page entries through relative runtime imports, re-exports, and validated Worker references. Unreachable migration source must not block builds; reachable invalid imports and unsupported syntax retain source diagnostics.
- A direct `.map()` over a named relative import of an exported JSON-safe immutable array folds to the array literal before render analysis, allowing build-known rows to emit complete HTML without list JavaScript.
- A top-level immutable result of a synchronous relative TypeScript calculation may feed direct static result-field reads in reactive JSX. Primitive and JSON-safe array state arguments use their build values initially and route-specific binding ESM reevaluates the imported helper after commits; package imports and dynamic result keys remain unsupported.
- One direct array field of that top-level relative calculation result may feed a keyed intrinsic JSX map. The compiler uses a route-specific evaluator to refresh a compiler-owned array anchor, then reuses existing keyed list and SVG ownership so retained keys preserve DOM identity. The field must remain a JSON-safe array on every update; indirect result aliases, dynamic fields, and nested calculated SVG lists remain unsupported.
- React icon package components are source migration targets, not runtime compatibility targets. Move only used icons into relative TSX components with direct intrinsic SVG roots; preserve explicit titles/roles for meaningful icons and `aria-hidden` for decorative icons. Build-folded icon conditions and unreachable icon modules must emit no handler or icon runtime artifacts.
- Named or aliased `Row` and `Col` imports from `react-bootstrap` may render directly with children and one static `className`. Kudzu erases the package import and lowers them to native `<div>` elements; `Row` emits `row`, while `Col` emits `col` or static numeric `xs`/`sm`/`md`/`lg`/`xl`/`xxl` span classes for integer literals 1 through 12. The application remains responsible for reachable Bootstrap CSS. Boolean/object/dynamic grid props, dynamic classes, spreads, default/subpath/namespace imports, and non-JSX references remain unsupported.
- Direct intrinsic handlers and directly returned relative custom-hook callbacks may use native `navigator.clipboard.writeText()` with application-owned success/failure state. Debounced state synchronization uses an existing dependency effect with `setTimeout()` and directly returned `clearTimeout()` cleanup so conditional/keyed/route ownership cancels pending work. A proven returned custom-hook timeout action lowers its private ref to compiler-owned state and reuses effect cleanup ownership. Do not add clipboard or timer runtimes; multiple timer refs, intervals, dynamic delays, and arbitrary timed callback graphs remain unsupported.
- `useId()` accepts no arguments and initializes one top-level `const` identifier in an ordinary component. It emits a deterministic build-time HTML ID and no browser capability. A keyed row may use it directly in intrinsic `id`, `htmlFor`, static ARIA IDREF, `form`, `headers`, `list`, and `popovertarget` attributes; cloned rows scope the ID by key path through existing list ownership. Aliases, text, handlers, arbitrary attributes, and component-prop forwarding remain unsupported.
- `forwardRef()` accepts one inline synchronous two-parameter render function whose object ref is forwarded exactly once to the direct intrinsic root. The compiler removes `ref` from ordinary props/rest and erases the wrapper; indirect render functions, callback refs, component-root forwarding, and repeated forwarding remain unsupported.
- Use function components, props, and children for composition.
- Declare local state exactly like React with `useState`; an anonymous synchronous zero-argument lazy initializer may directly return a serializable primitive, plain-object, or array literal. Reduced `useReducer` support requires a pure synchronous two-parameter reducer imported from a relative TypeScript module. Its optional inline, same-file, or relative-imported synchronous one-parameter initializer may derive a directly serializable literal only from a directly serializable initial argument. Dispatch may cross one direct prop boundary into a specialized same-file or relative-imported synchronous component, including a direct keyed row, and one inline or simple `const` callback containing dispatch may cross one additional relative-imported intrinsic component boundary. These specializations accept destructured directly serializable literal prop defaults, direct inline or calling-component `const` object prop spreads, forwarded JSX children, and rest props forwarded exactly once to a direct intrinsic root.
- Repeated ordinary same-file and relative-imported child components own independent state IDs. Reactive conditional branches own child state, remove it on unmount, and recreate it from the serialized initializer on remount without a browser component tree.
- A direct JSON-safe primitive parent state passed to a destructured ordinary child prop remains a signal for child DOM bindings and effect dependencies. Repeated calls share the parent state while owning independent effects; conditional removal cleans up and remount recreates the child effect.
- A direct JSON-safe object parent state may pass unchanged to a destructured same-file or relative-imported component when that child directly maps one array-valued `prop.field` into keyed intrinsic JSX. Direct one-segment scalar fields may feed sibling bindings and the same direct array field may feed one effect dependency; ComponentAnalysis links all consumers to the parent SignalIR, selected effects compare with `Object.is`, and binding-backed keyed ownership preserves retained rows. Repeated and conditional calls own independent effects without browser components or authored field state. Dynamic/computed paths, property aliases, prop mutation, child state/ref/ID hooks, opaque call-site values/spreads, and fields not proven by the direct map remain unsupported.
- One direct static array field of ordinary local object state may root a keyed selector pipeline with nested direct-property lists. Kudzu reuses a binding-backed root anchor and existing nested keyed ownership so immutable whole-object replacement preserves retained rows, latest handlers, and descendant cleanup. Dynamic/computed paths, multi-segment roots, mutation, and non-array field values remain unsupported.
- Effect dependency arrays may contain multiple direct primitive states or supported props. Existing commit batching compares every value with `Object.is` and reruns the effect once when one or more values change. Direct property paths over ordinary object state and top-level immutable locals derived through supported pure primitive expressions may also appear in the array; source states schedule comparison, and the expression is substituted into setup and cleanup handlers so unchanged selected values do not rerun the effect. Whole-object and dynamic property dependencies remain unsupported.
- An ordinary component may declare top-level `useRef(null)` and `useRef(0)` values when every direct `.current` reference belongs exclusively to one inline block-bodied effect setup, its nested callbacks, and cleanup. Kudzu moves those refs into an invocation-private effect closure, preserving SDK handles, WebSockets, generation invalidation, dependency replacement, BFCache-owned mount effects, and exact cleanup without ResourceIR or a runtime. JSX DOM refs remain component-owned; aliases, nonzero initializers, cross-effect/event use, and escaped ref objects remain unsupported.
- One top-level `useRef(null)` retained package-instance handle may instead be assigned once by one empty-dependency mount effect or by one guarded lazy activation effect directly inside its literal package import `.then()` callback, reset directly to `null` by that effect's cleanup, and read by later dependency effects in the same component. Kudzu lowers the ref object to existing owner-scoped state so conditional removal disposes the instance and remount creates a fresh handle. The ref must remain unattached, every use must be direct `.current`, update effects may not write it, and only one retained handle is supported per component; no resource registry, loader, or widget runtime is added.
- An ordinary component effect may exclusively own a zero-initialized `useRef(0)` animation-frame handle when one local callback resets it, one direct scheduler assigns `requestAnimationFrame()`, and effect cleanup directly cancels the pending frame. Kudzu lowers the ref into the invocation-private effect closure; scroll/resize coalescing adds no animation runtime. Repeated scheduling assignments and missing cancellation remain unsupported.
- An imperative canvas may keep one direct `useRef(null)` DOM ref while one inline effect owns its local drawing state, recursive `requestAnimationFrame()` loop, `IntersectionObserver`, native listeners, and exact cleanup. Kudzu preserves bare browser `IntersectionObserver` and `performance` references in route-specific effect ESM; it does not add a canvas runtime. Mutable refs shared across effects/handlers, uncancelled loops, and observers without disconnect cleanup remain unsupported migration shapes.
- Static locale migrations generate every known locale through `getStaticPaths()`, replace package Link routing with a relative component that prefixes native anchor hrefs from the build-known locale prop, and may use one `/` mount effect to choose a stored locale or inspect `navigator.languages` before `location.replace()`. Runtime-resource `react-i18next` `useTranslation()` calls receive a migration diagnostic rather than silently folding one language or shipping i18next. Request-time `Accept-Language` negotiation remains a host/edge concern; do not add a server or router runtime for it.
- A top-level component `const supported = "literal" in navigator` may control exactly one direct `supported && <Branch />` JSX site. Kudzu emits a false static fallback, evaluates the immutable capability once in an existing mount effect, and reuses state-conditional ownership so unsupported browsers receive no branch DOM or handlers. Escaped values, aliases, dynamic names, boolean composition, ternaries, `canShare()`, and other browser globals remain unsupported.
- A direct top-level `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` may initialize one boolean when all three callbacks are inline, the subscribe callback and browser snapshot read one identical static `window.matchMedia("literal")` query, the server snapshot is `false`, and subscribe adds then removes the same `change` listener. Kudzu lowers it to false static HTML plus an existing state/effect pair. Parameterized/imported media hooks, dynamic queries, legacy listeners, arbitrary external stores, non-boolean snapshots, and missing cleanup remain unsupported.
- Dependency effect replacement invalidates the previous invocation before cleanup, so setters captured by late promises or fetch responses cannot overwrite newer state. TanStack Query-shaped migration moves build-known reads to async pages/components and browser-only reads to inline effects with application-owned loading/error/data state and primitive refetch dependencies; Apache Answer-shaped SWR reads follow the same owned-effect path with page/order query signals and keyed results. Do not add a query cache, Provider, retry scheduler, SWR, or TanStack runtime.
- An effect setup callback and its directly returned cleanup may reference one top-level simple `const` function declared in the same component. The compiler substitutes those functions into the existing effect handler; indirect aliases, dynamic selection, parameters, and cross-component references remain unsupported.
- Event handlers use normal synchronous or async JavaScript. State setters update logical state immediately and DOM writes batch at synchronous-turn boundaries.
- Pending async intrinsic handlers lose state-write, queued-commit, and captured-ref authority when enhanced navigation, keyed/conditional removal, or document disposal releases their mounted DOM owner. Late direct/captured setters and queued commits become no-ops, and captured object refs resolve to `null`; promises and ordinary reads may finish, and Kudzu adds no task scheduler.
- Reactive JSX text and attributes may reference a top-level immutable local derived recursively through supported pure primitive expressions from direct state. The compiler substitutes the expression and subscribes its source states. A fixed-locale `new Intl.NumberFormat("literal").format(Math.round(expression))` chain is also supported for reactive display formatting; dynamic locales/options, arbitrary calls, mutation, cycles, and structural JSX locals remain unsupported.
- A direct setter or inline/simple `const` setter callback may cross one same-file or relative-imported component boundary and two additional direct forwarding boundaries before one or more intrinsic handlers invoke it, allowing ordinary value adapters without serializing a function. The first boundary may pass a direct parent setter through one `on*` prop or a matching `set*` prop; additional forwarding remains restricted to direct `on*` props. A component may forward the same callback directly through multiple component `on*` props, and a leaf may call it once in each of multiple direct intrinsic `on*` handlers. Each forwarding site must pass the destructured callback directly; a fourth callback boundary, intermediate adapters, aliases, spreads, repeated calls within one handler, additional `set*` forwarding, and non-handler uses remain unsupported. Specialized children may own directly serializable `useState()` values or initialize state from one direct parent state prop whose authored initializer is a serializable primitive, plain object, or array; zero-argument `.toString()` remains primitive-only. They may also own one or more `useId()` values, supported effects, and object refs initialized with `null`. Prop initializer aliases, property paths, composed expressions, and other dynamic initializers remain unsupported. They may recursively render presentation components; hookful nested components require an unconditional or statically truthy path. A parent-owned `null`-initialized object ref may follow the same proven tree to one direct intrinsic root. Conditional removal drops the handler with the DOM, deletes child state, resolves refs to `null`, and runs effect cleanup; remount creates fresh ownership and dependency effects synchronize prop-derived state without a browser component instance.
- A specialized child initialized from one direct parent array-state prop may call its matching direct `set*` setter prop in one top-level inline effect with exact `[state, setter]` dependencies. The compiler removes the stable setter dependency and compares the child array state by identity through existing effect ownership. Setter aliases, composed values, mismatched parent pairs, cleanup, additional callback uses, and automatic parent-to-draft synchronization remain unsupported.
- Command-only setter and `console.log(label, state)` handlers use the optimized behavior path; other handlers compile to external ESM.
- Native handlers may capture serializable component locals and destructured props. Relative imported helpers and supported reducer imports compile into handler ESM; non-serializable captures remain unsupported.
- A keyed row may contain multiple keyed maps over direct parent-item array properties at any nesting depth. Intrinsic, same-file, directly exported same-file, or relative-imported rows support recursive component specialization, static/keyed JSX reuse, destructured directly serializable literal prop defaults, direct analyzable prop spreads, direct intrinsic rest forwarding, forwarded JSX children, nested item conditions, latest-item handlers, multiple directly serializable `useState` values, one object draft initialized from the direct keyed item prop, effects, and object refs initialized with `null`; key paths own hook state across updates/reorder and release it on removal. Re-adding a released key initializes a fresh draft from the current item; aliases, property paths, and composed item initializers remain unsupported.
- A flat keyed row's pure text or attribute expression may combine the current item/index with direct primitive parent state, enabling selected-row classes and ARIA state without remounting rows. Object/array state, derived local captures, structural conditions, nested-row parent state, mutation, and arbitrary calls remain unsupported.
- An expression-bodied keyed `map` callback with exactly one item parameter may return `condition && <Row />` or `condition ? <Row /> : null`. The compiler lowers the pure item/direct-primitive-parent-state condition into the existing filter selector, so omitted rows unmount and re-entry creates fresh ownership; nested maps may use item-only conditions. Map indexes, alternate JSX fallbacks, block bodies, arbitrary captures, and impure conditions remain unsupported.
- A block-bodied keyed `map` callback may declare one top-level `const` computed from a direct child collection through the supported pure selector pipeline and then return JSX. The alias must feed exactly one nested keyed list source.
- An immutable local collection alias may feed multiple keyed list sites when every alias reference is a statically analyzable collection source. Mixed non-collection reads remain unsupported.
- A relative-imported named or default synchronous one-parameter function may transform a supported collection argument through one directly returned pure selector pipeline. The compiler composes its selector without executing or shipping the function; captures, package/namespace imports, async functions, and additional statements remain unsupported.
- Supported collection pipelines may use immutable `slice(start, end?)` with direct numeric literals or expressions over direct primitive state, enabling bounded pagination without a new runtime. Arbitrary calls in slice bounds remain unsupported.
- Reactive search may compose `filter` with supported pure string methods and direct primitive state. Immutable sorting uses `toSorted((left, right) => expression)` with exactly two identifier parameters; comparator expressions may read item properties and direct primitive state, while mutating `sort()` remains unsupported.
- Reactive conditionals and flat intrinsic keyed lists may render inside SVG. Compiler-generated branch and row prototypes are parsed in the actual SVG parent context and reuse existing ownership; keyed-item conditions, nested SVG lists, MathML structures, and namespaced attributes remain unsupported.
- Accessible selected-point SVG charts use ordinary parent state, focus/click/keyboard handlers on flat keyed SVG rows, and an external HTML tooltip. Retained rows read the latest item after collection updates; do not add a chart runtime for this composition.
- Put routes in `src/pages`; `index.tsx` maps to `/`.
- Relative source CSS imports follow each page's reachable TypeScript import and re-export graph. Only routes that reach a stylesheet link it; declare truly global styles through `kudzu.config styles`. Enhanced navigation loads destination styles before route replacement, retains shared layout links by URL and DOM identity, and removes outgoing route styles.
- Do not add a VDOM, hydration, state library, general component runtime, or default SPA router.
- Run `npm run check` and `npm test` after changes.
